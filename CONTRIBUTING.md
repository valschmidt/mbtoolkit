# Contributing to Community GSF Toolkit

Thank you for your interest in contributing to the Community GSF Toolkit! This document provides guidelines and instructions for contributing.

## Getting Started

1. **Fork the repository** on GitHub
2. **Clone your fork** locally
3. **Set up your development environment**:
   ```bash
   pip install -r requirements.txt
   ```
4. **Create a branch** for your contribution:
   ```bash
   git checkout -b feature/your-feature-name
   ```

## How to Contribute

### Reporting Issues

- Use GitHub Issues to report bugs or request features
- Include:
  - Clear description of the issue
  - Steps to reproduce (for bugs)
  - Expected vs. actual behavior
  - Environment details (OS, Python version, etc.)
  - Sample GSF files if relevant (ensure no sensitive data)

### Submitting Code Changes

1. **Write clean, readable code** following Python best practices
2. **Add tests** for new functionality (when test suite is available)
3. **Update documentation** as needed
4. **Commit messages** should be clear and descriptive
5. **Submit a Pull Request** with:
   - Clear description of changes
   - Reference to related issues
   - Tests and documentation updates

### Code Style

- Follow PEP 8 Python style guidelines
- Use meaningful variable and function names
- Add docstrings to functions and classes
- Include type hints where appropriate

### Testing

- Ensure existing functionality still works
- Test with sample GSF files
- Include edge cases and error conditions

## Development Workflow

1. Keep your branch up to date with `main`
2. Make focused, atomic commits
3. Write clear commit messages
4. Test your changes thoroughly
5. Update documentation as needed

## Pull Request Process

1. Ensure your code follows project conventions
2. Update documentation if needed
3. Add tests if applicable
4. Submit PR with clear description
5. Respond to review feedback promptly

## Questions?

- Open an issue for questions or discussions
- Join community discussions (channels to be established)
